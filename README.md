# Reverse Seam-Carving

Reverse Seam-Carving (RSC) redistributes placement density to create routing channels
between denser blocks of cells. This repository provides the OpenROAD flow,
the repaired mapped netlists used by that flow, and OpenROAD measurement data
for reviewing the experiments.

The baseline and seam-carved configurations use the same repaired netlist,
floorplan utilization, and placement/routing settings. Seam geometry and the
requested utilization increment within the blocks distinguish the carved cases.

This repository accompanies the DAC27 submission "*Reverse Seam-Carving: Structured Whitespace Preconditioning for Fixed-Die P&R*".

## Flow modules

```text
flow/openroad/
├── flow.tcl             Stage ordering and GRT/DRT entry point
├── config.tcl           User parameters and design/technology paths
├── common.tcl           Output-path and text-file helpers
├── platform.tcl         Libraries, design import, floorplan, routing layers
├── seams.tcl            Seam intervals, disjoint rectangles, density balance
├── density.tcl          Blockage-adjusted global-placement target
├── io.tcl               IO pin placement
├── placement.tcl        Initial/main placement and legalization
├── cts.tcl              Clock-tree construction
├── timing.tcl           Estimated/extracted timing reports
├── global_route.tcl     Global routing and checkpoint output
├── detail_route.tcl     Detailed routing from the saved checkpoint
├── build_handoff.tcl    Reconstruct an input ODB from repaired Verilog
├── preprocess.tcl       Optional preprocessing of an unrepaired input
└── tie_cells.tcl        Constant-net mapping onto tie drivers
```

`seams.tcl` owns the seam geometry and block-density calculation. Placement,
clock-tree construction, and routing use that geometry through the stage
coordinator. Detailed routing loads the saved global-route checkpoint.

The source links provide the upstream RTL. The supplied CVA6, SweRV, and
MemPool netlists use macro-free variants of those designs. TPU uses
`N=8`, `DW=8`, and `ACCW=32`; its RTL is also available in
[ORFS](https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts/tree/master/flow/designs/src/tpu).


Each `designs/<identifier>/` directory contains `netlist.v` and `constraints.sdc`. 
Netlists are generated by Cadence Genus, with buffers inserted for timing closure.
They are preprocessed in OpenROAD and then frozen until post-placement CTS. 
The preprocessing maps constant nets onto ASAP7 tie cells, repairs tie-cell fanout, and runs
ERC repair with `repair_design -pre_placement`, allowing signal buffering and cell resizing.
Baseline and RSC share this resulting netlist. 

The data contains OpenROAD results. The `flow/genus/` directory provides
the Genus synthesis driver and its library and design configuration.

## OpenROAD flow

The flow performs the following stages.

1. Import the repaired netlist and create a floorplan from its cell area.
2. Generate vertical and horizontal seams on the legal site/row grid.
3. Run initial placement with `-skip_io`.
4. Assign IO pins and fix their locations.
5. Run fresh routability-driven placement with the seams applied.
6. Remove partial density screens for detailed legalization and legalize cells.
   Hard blockages remain.
7. Build the clock tree and legalize its buffers.
8. Run global routing and save its OpenDB checkpoint and routing guides.
9. Restore that checkpoint for detailed routing, followed by extraction and
   timing reports.

The placement-stage density screens shape the global placement. Their partial
constraints are removed by the existing legalization procedure, so the final
placement can fill part of the requested channels.

The signal netlist stays fixed after preprocessing, except for CTS. CTS uses
`BUFx2_ASAP7_75t_R` buffers and `-repair_clock_nets` to construct and repair
the clock network. No additional buffers are inserted.

Signals and clocks use M1--M6. Global routing applies a 25% layer-capacity
derate, matching the ORFS ASAP7 adjustment. This encourages routing to spread
across layers and improves layer distribution. Global routing allows residual
congestion and uses 50 congestion iterations (default). Detailed routing uses 32
iterations and restores the saved global-route guides. Clean DRT summary
entries have zero reported violations.

## Running the OpenROAD flow

The experiments use OpenROAD commit `ab8ddb7`.

Design settings and bundled library paths are defined in
`flow/openroad/config.tcl`.

From the repository root, reconstruct the repaired input checkpoint and run
the global-route stage.

```bash
openroad -exit flow/openroad/build_handoff.tcl
openroad -exit flow/openroad/flow.tcl
```

Set `cfg(stage)` to `detail` in `config.tcl` to continue from the saved
global-route database and guides, then run the same flow entry point.

```bash
openroad -exit flow/openroad/flow.tcl
```

`flow/openroad/preprocess.tcl` provides the preprocessing procedure for
an alternate mapped input. Input and output paths are configured in
`flow/openroad/config.tcl`.

## Results and CSV definitions

| File | Contents |
| --- | --- |
| `data/design_statistics.csv` | Repaired pre-CTS instance, logical-net, IO, and cell-area counts |
| `data/doe.csv` | Planned configurations for the experiment set |
| `data/openroad_measurements.csv` | Available per-configuration/per-seed GRT and DRT measurements and completion status |
| `data/openroad_summary.csv` | Best measured configurations per design, utilization, overflow, and routing stage |
| `data/openroad_stage_metrics.csv` | Per-run HPWL before and after each legalization step, utilization, and seam geometry of the `control` experiment |

`doe.csv` lists planned configurations for the experiment set. Measurement
rows record available results for each configuration and seed. Reused results
appear once in the measurement data. Runs that time out are marked
`incomplete`.

The summary minimizes configuration-median wirelength over the eligible
completed samples. It compares the RSC median against the median available
baseline at the same design, utilization, overflow target, and routing stage.
An `rwl_ratio` below 1 indicates improvement. `improvement_pct` is
`100 * (1 - rwl_ratio)`. Baseline and RSC sample counts identify partial coverage.
Summary rows report absolute RSC wirelength. Ratios are populated for rows
with measured baselines.

| Measurement column | Definition |
| --- | --- |
| `experiment` | `control` for overflow 0.05, or `overflow` for the weakening study |
| `design`, `config`, `placement_seed` | Portable identifiers for a measurement |
| `util_pct` | Floorplan utilization as a percentage |
| `kind` | Baseline, combined seams, or a single-axis control |
| `placement_overflow` | Main global-placement stopping target |
| `grt_status` | Saved global-route completion state |
| `grt_wl_um` | Native OpenROAD global-route wirelength in micrometers |
| `drt_status` | `completed_clean`, `failed`, `incomplete`, or `not_run` |
| `drt_wl_um` | Native detailed-route wirelength in micrometers, when available |
| `drt_drc` | Saved detailed-route violation count |

Wirelength columns use native router measurements, including routed clock
networks. DRT summary comparisons use clean completed samples. Per-run rows
retain available wirelength measurements and native violation counts. Empty
fields indicate unavailable measurements.

`openroad_stage_metrics.csv` has one row per run of the `control` experiment,
identified by `design`, `util_pct`, `config` and `placement_seed` as in
`openroad_measurements.csv`. Empty fields indicate stages that a run did not
reach.

| Stage-metric column | Definition |
| --- | --- |
| `gp_hpwl_um` | HPWL at the end of global placement, in micrometers |
| `dp_hpwl_um` | HPWL after legalization of the placement |
| `cts_hpwl_before_dp_um`, `cts_hpwl_after_dp_um` | HPWL before and after the legalization that follows CTS |
| `utilization_before_dp_pct` | Utilization before legalization of the placement, in percent |
| `utilization_before_cts_dp_pct` | Utilization before the legalization that follows CTS; the difference to the previous column is the clock-buffer area |
| `seam_fraction` | Fraction of the core area covered by seams |
| `seam_utilization` | Requested seam utilization; values below 0.05 are realized as hard blockages |
| `core_width_um`, `core_height_um` | Core dimensions in micrometers |

`design_statistics.csv` counts the repaired netlist before CTS. Logical-net
counts cover connected non-supply nets, including clock nets.
Cell area is the sum of instantiated LEF master areas, in square micrometers.

## SeamGain

`seamgain/` contains the SeamGain model, which predicts the routed-wirelength
reduction of an RSC configuration from one uniform reference run and selects
the configuration of a design. `seamgain/README.md` describes the model and the
scripts.

```bash
python3 seamgain/evaluate.py     # accuracy, unseen designs, configuration selection
python3 seamgain/topk.py         # selection with k RSC runs
python3 seamgain/select_config.py --metrics uniform_metrics.json \
    --core-width-um 75.762 --core-height-um 75.6
```

The first two commands reproduce the SeamGain results of the paper from
`data/openroad_measurements.csv` and `data/openroad_stage_metrics.csv`. The
third selects the configuration of a design from the metrics file of its
uniform run (`openroad -exit -metrics uniform_metrics.json flow/openroad/flow.tcl`).
